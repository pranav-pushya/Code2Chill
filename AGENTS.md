# Code2Chill Working Instructions

## Required living documentation

The project owner requires detailed build and viva documentation updated after every task or implementation step.

- Read `docs/BUILD_AND_VIVA_GUIDE.md` and the relevant part of `WEBSITE_ROADMAP.md` before project work.
- Update the guide after each task or independently completed step, before reporting completion. For multi-step work, document steps as they finish.
- Record the objective, actual changes and files, how the result works, rationale and tradeoffs, validation and results, limitations, and relevant viva questions with answers.
- Include research, planning, documentation work, and failed or blocked attempts that affect the project. Label status accurately.
- Keep the current implementation explanation consistent with the code. Never describe proposed functionality as implemented.
- Maintain a chronological task log with unique IDs and actual dates. Do not invent historical dates, commands, versions, or test results.
- Update roadmap checkboxes only when the corresponding work is actually complete.
- Use plain language and relative repository links in documentation. Never include secrets or private applicant data.
- Documentation is part of task completion; no separate permission is needed for these updates.

## Existing rules

- Follow `GEMINI.md` alongside these instructions.
- Do not commit or push unless the user explicitly requests it. Use short, simple commit messages when requested.
- Ask before adding Motion, GSAP, React Bits, Magic UI, or Lenis unless the conversation already explicitly authorizes the addition.
